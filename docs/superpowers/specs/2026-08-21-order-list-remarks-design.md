# 订单列表备注展示设计

## 背景

Ant Design Vue 订单列表已经从订单接口获取 `remark`（商家备注）和 `userRemark`（用户备注），但列表页目前只在备注编辑弹窗中使用商家备注。需要参考有赞的订单列表，在外层订单行下展示备注，便于运营快速查看。

## 目标

- 在订单列表外层订单行下展示商家备注和用户备注。
- 商家备注、用户备注分别展示，避免两类信息混淆。
- 空备注不渲染对应行；两类备注都为空时不显示备注区域。
- 保持现有订单接口、查询条件、表格列和备注编辑流程不变。

## 方案

复用订单列表现有的展开行内容插槽，在商品明细之后追加备注区域。备注区域根据当前订单动态生成可展示的备注项：

- `remark` 非空时显示“商家备注：{内容}”。
- `userRemark` 非空时显示“用户备注：{内容}”。
- 备注值按字符串去除首尾空白后判断是否为空，但展示原始备注内容。
- 两项均为空时不渲染备注容器，避免在订单间产生空白。

备注区域使用轻量的上下排列布局，并以与有赞截图相近的提示色区分于商品明细；不新增独立卡片或横向表格列，避免压缩订单信息。长文本允许换行。

## 数据流与边界

列表接口返回的 `MallOrderApi.Order.remark` 与 `MallOrderApi.Order.userRemark` 直接作为展示数据。备注编辑仍调用现有 `updateOrderRemark`，成功后刷新列表即可看到最新商家备注。用户备注只读展示，不增加修改入口。

## 测试

新增备注展示逻辑的单元测试，覆盖：

1. 商家备注和用户备注均非空时生成两条备注。
2. 只有一类备注非空时只生成对应的一条备注。
3. 两类备注为空或仅包含空白时不生成备注项。

同时运行该测试文件及 Ant Design 应用的类型检查或等价的针对性校验，确认不影响现有订单列表逻辑。

## 非目标

- 不修改其他 UI 实现（`web-antdv-next`、`web-ele`、`web-naive`、`web-tdesign`）。
- 不调整后端接口、订单详情页或订单筛选条件。
