# 商品列表推广入口设计

## 背景

运营人员修改商品价格或商品信息后，需要进入小程序再次查找商品，才能取得推广素材。该流程步骤多，并可能因小程序缓存或选错商品而使用过期内容。

本功能在管理后台商品列表中增加推广入口。运营可以直接针对当前出售中的商品生成推广海报、商品卡片、H5 二维码图和推广链接。推广内容支持公共店铺身份，也支持按需指定推广员，并尽量保持与小程序商品推广素材一致。

## 目标

- 在商品列表内完成推广素材生成，不离开当前列表工作流。
- 每次打开推广弹窗时读取最新商品详情，确保价格、图片和文案即时更新。
- 支持公共店铺推广和指定推广员推广。
- 输出可下载的商品海报、商品卡片、H5 二维码图，以及可复制的推广链接。
- 复用现有会员、商品、小程序码和商城 H5 配置，不新增后端接口。
- 所有产品和 UI 代码仅修改 `apps/web-antd`。

## 非目标

- 不从后台网页直接唤起微信好友或朋友圈分享。
- 不实现微信原生小程序分享卡片；“商品卡片”是可下载的横版 PNG 图片。
- 不保存生成记录，不把图片上传到服务端，也不建设素材管理库。
- 不对仓库中、已售罄、警戒库存或回收站商品开放推广入口。
- 不修改其他前端应用目录或后端工程。

## 入口与范围

在 `apps/web-antd/src/views/mall/product/spu/index.vue` 的行操作中增加“推广”入口，并使用分享图标。入口仅在“出售中”页签显示。

点击入口打开约 960px 宽的推广弹窗。关闭弹窗不改变商品列表当前筛选条件、页签、分页或滚动位置。

弹窗打开后通过商品 ID 调用商品详情接口，而不是直接使用列表行数据。详情返回后再次校验商品销售状态；如果商品已不再出售，停止生成并提示运营刷新列表。

## 推广身份

弹窗默认选择“店铺公共”，并生成 `shareId=0` 的推广内容。店铺身份使用：

- 名称：`VITE_APP_TITLE`
- Logo：`/branding/logo-mark.png`

运营可以切换为“指定推广员”，随后通过可搜索的会员选择器选择一个会员。选中结果显示头像、昵称和手机号末四位，以降低同名误选风险。推广内容使用会员 ID 作为 `shareId`，图片身份区使用会员头像和昵称。

会员头像为空或加载失败时，回退到店铺 Logo；昵称为空时使用可识别的会员编号兜底。没有会员查询权限时隐藏“指定推广员”选项，公共推广仍然可用。

## 推广地址与追踪参数

推广参数沿用小程序 `spm={shareId}.{page}.{query}.{platform}.{from}` 规则。普通商品页面类型为 `2`，商品 ID 作为页面查询值，公共推广员 ID 为 `0`。构造逻辑集中在纯函数中，避免图片、二维码和复制链接分别拼接导致不一致。

小程序素材使用：

- 页面：`pages/index/index`
- 场景值：`spm={shareId}.2.{spuId}.3.2`，即微信小程序平台和海报来源
- 二维码接口：现有 `/app-api/member/social-user/wxa-qrcode`

H5 地址使用 `VITE_MALL_H5_DOMAIN`，并附加 `spm={shareId}.2.{spuId}.1.3`，即 H5 平台和链接来源。地址通过 `URL` API 构造，正确处理域名已有查询参数的情况。后台请求小程序码时继续携带当前租户信息。商品卡片属于图片素材，与商品海报共用小程序场景值。

## 弹窗结构

弹窗顶部展示紧凑的商品摘要：商品主图、名称、当前售价和市场价。摘要下方使用分段控件选择“店铺公共”或“指定推广员”。

主体使用以下四个页签，不在页签中嵌套装饰性卡片：

### 商品海报

- 输出尺寸：600 x 1000 PNG。
- 内容：身份头像和名称、商品主图、商品标题、当前售价、划线市场价、小程序码及扫码提示。
- 视觉结构与小程序现有商品海报保持一致，适配后台品牌色和品牌 Logo。
- 操作：下载 PNG；失败时原位重试。

### 商品卡片

- 输出尺寸：1000 x 800 PNG。
- 内容：商品主图、身份信息、标题、当前售价、划线市场价和小程序码。
- 采用横版、信息密度较高的构图，适合运营直接发送到群聊或其他内容渠道。
- 操作：下载 PNG；失败时原位重试。

### H5 二维码

- 输出方形 PNG。
- 内容：店铺品牌、商品缩略图、商品名称、价格、H5 二维码及扫码提示。
- 二维码内容是当前推广身份对应的 H5 商品地址。
- 操作：下载 PNG；失败时原位重试。

### 推广链接

- 展示完整 H5 商品推广地址。
- 提供复制链接和新窗口预览。
- 不生成或模拟微信原生分享行为。

## 模块边界

### `promotion-modal.vue`

负责弹窗生命周期、商品详情加载、推广员选择、页签状态、生成状态、错误展示、下载和复制操作。该组件不直接拼接追踪参数，也不包含底层 Canvas 绘制细节。

### `promotion-share.ts`

提供无副作用的推广数据构造函数，包括：

- 公共或推广员身份归一化
- `spm` 和小程序场景值生成
- H5 URL 生成
- 价格展示数据归一化
- 素材缓存键生成

### `promotion-renderer.ts`

负责浏览器端图片生成，包括：

- 跨域图片加载和超时处理
- 商品海报布局
- 商品卡片布局
- H5 二维码图布局
- 中文标题测量、两行截断和省略号处理
- Canvas 到 PNG Blob 的导出

渲染器接收完整、已归一化的数据，不请求业务接口。二维码生成使用项目工作区已有的 `qrcode` 依赖能力，并在 `web-antd` 中显式声明直接依赖（如当前包尚未声明）。

### API 适配

商品详情继续复用 `#/api/mall/product/spu`，会员搜索继续复用 `#/api/member/user`。新增一个 `apps/web-antd` 内的小程序码 API 封装，调用现有 App API 的完整地址，并复用当前请求层的租户头和统一错误处理。

## 状态与缓存

图片按需生成：首次进入图片页签时开始生成，避免弹窗打开时同时执行多个 Canvas 任务。

生成结果的内存缓存键包含商品 ID、影响素材的商品字段摘要、推广身份和素材类型。商品详情或推广身份变化时，相关缓存全部失效。关闭弹窗时释放所有 Blob URL，避免长时间使用后台造成内存累积。

所有图片生成结果只存在于浏览器内存。下载时使用明确、可识别的文件名，例如 `商品名称-商品海报.png`。

## 异常处理

- 商品详情加载失败：弹窗展示加载失败状态和重试入口。
- 商品状态已变化：停止生成并提示刷新商品列表。
- 商品主图加载失败：不生成错误素材，展示具体失败信息和重试入口。
- 推广员头像加载失败：回退到店铺 Logo，不阻断生成。
- 小程序码接口失败：海报和商品卡片分别展示失败状态；H5 二维码和推广链接保持可用。
- H5 域名缺失或无效：禁用 H5 二维码和推广链接页签，并提示检查 `VITE_MALL_H5_DOMAIN`。
- Canvas 导出失败：保留预览上下文并允许重新生成。
- 复制 API 不可用：使用兼容性复制方案；仍失败时展示可手动选择的完整链接。

生成和下载操作均需要防止重复提交。切换推广身份期间禁用下载，避免使用旧身份素材。

## 可访问性与响应式

- 页签、分段控件、会员选择器和按钮均支持键盘操作。
- 图标按钮提供可访问名称；主要命令采用图标加文本。
- 图片预览使用固定宽高比容器，加载、错误和实际图片不会引发布局跳动。
- 弹窗在常规桌面宽度使用左右分区；较窄后台窗口切换为上下布局，文本和操作按钮不得重叠。
- 价格、商品标题和错误信息具备明确的文本对比度，不仅通过颜色表达状态。

## 测试与验收

### 单元测试

- 公共推广生成 `shareId=0`。
- 指定推广员使用正确会员 ID、头像和昵称。
- `spm`、小程序场景值和 H5 URL 与小程序规则一致。
- H5 域名已有查询参数时仍正确生成地址。
- 价格和市场价格式正确，无市场价时不绘制划线价格。
- 中文、英文和混合长标题稳定截断为两行。
- 不同商品、身份或素材类型生成不同缓存键。

### 组件测试

- “推广”入口只在出售中页签显示。
- 打开弹窗时重新请求商品详情。
- 商品状态变化时阻止生成。
- 无会员权限时仅展示公共推广。
- 切换推广员后所有旧素材失效。
- 图片、小程序码、剪贴板失败时进入正确的降级状态。
- 成功下载时使用正确文件名并释放临时 URL。

### 验证命令与视觉检查

- 运行新增或受影响的 Vitest 文件。
- 运行 `web-antd` 相关 TypeScript 检查。
- 运行 `pnpm build:antd`。
- 启动 `pnpm dev:antd`，在常规桌面和较窄后台窗口检查弹窗布局。
- 核对 600 x 1000、1000 x 800 和方形三种输出图片的像素尺寸、二维码可扫性、文本截断、价格显示和身份归属。

## 验收标准

1. 运营可从出售中商品列表一键打开推广弹窗，其他商品状态不显示入口。
2. 弹窗使用商品最新详情，修改价格或商品信息后无需进入小程序查找。
3. 默认可生成公共店铺推广内容，也可选择会员生成带该推广员归属的内容。
4. 三种 PNG 均可预览、下载且尺寸正确；推广链接可复制并打开。
5. 图片内容中的商品、价格、身份和二维码始终来自同一份推广数据。
6. 失败场景不会下载空白、半成品或归属错误的图片。
7. 相关单元测试、类型检查和 Ant Design 应用构建通过。
