# 订单编辑保存反馈设计

## 背景

订单详情页的价格、备注、收货地址、普通发货和微信发货弹窗都能完成保存，但提交期间没有显式的进行中反馈，接口失败时也缺少统一的失败提示。用户无法判断保存是否已经开始，容易重复点击或误以为操作无效。

## 目标

- 统一覆盖订单详情页的五类编辑保存动作。
- 点击保存后立即展示持久的“保存中...”反馈，并沿用现有弹窗锁定机制阻止重复提交。
- 保存成功后关闭进行中反馈、关闭弹窗、触发详情刷新并展示通用成功提示。
- 保存失败后关闭进行中反馈、解除弹窗锁定、保留表单内容并展示通用失败提示，允许用户重试。
- 不改变全局 `useVbenModal` 行为，也不影响其他模块的确认、查询或上传操作。

## 方案

在 `apps/web-antd/src/views/mall/trade/order` 下新增一个轻量的保存反馈工具。工具接收一个异步保存函数和可选的 loading 文案，使用 Ant Design Vue `message.loading({ duration: 0 })` 创建持久提示，并在 `try/finally` 中确保提示句柄始终被关闭；成功和失败提示使用现有 `$t('ui.actionMessage.operationSuccess')` 与 `$t('ui.actionMessage.operationFailed')` 文案。

各订单编辑弹窗仍负责自己的表单校验、请求参数转换、`modalApi.lock/unlock`、关闭弹窗和 `success` 事件。请求调用通过工具包装，失败由工具消费并提示，避免弹窗关闭或详情刷新在失败时发生。

## 涉及组件

- `price-form.vue`：调整价格。
- `remark-form.vue`：修改订单备注。
- `address-form.vue`：修改收货地址。
- `delivery-form.vue`：普通快递发货。
- `wechat-delivery-form.vue`：微信物流发货。

## 错误处理与状态流

1. 表单校验失败：不显示保存反馈，不锁定弹窗，保留当前校验行为。
2. 请求开始：锁定弹窗并显示“保存中...”。
3. 请求成功：关闭 loading，关闭弹窗，触发 `success`，由详情页重新读取订单数据，然后显示成功提示。
4. 请求失败：关闭 loading，显示失败提示，不关闭弹窗；`finally` 中解除锁定。

## 测试策略

- 为保存反馈工具添加 Vitest 单元测试，验证成功、失败和异常时 loading 句柄均被关闭，且成功/失败提示只在对应分支触发。
- 运行该测试文件，再运行 `pnpm exec vitest run` 覆盖 `apps/web-antd` 相关测试；必要时运行 `pnpm --filter @yudao/web-antd check:type` 或仓库现有等价类型检查命令。

## 非目标

- 不重构所有应用的编辑弹窗。
- 不修改后端接口、订单数据结构或全局请求拦截器。
- 不引入新的 UI 组件库或视觉样式。
